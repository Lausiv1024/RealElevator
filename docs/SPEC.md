# Real Elevator 仕様書

2026-10-13 時点

## 概要とコンセプト

日本式エレベーターの操作感と挙動を、マイクラのドット絵の世界観で再現するNeoForge用MODを作る。

- **操作**：実機の日本式エレベーターと同じ操作方法（乗場ボタン、かご操作盤、開・閉ボタン、2度押しキャンセルなど）
- **見た目**：マイクラのドット調を維持しつつ、日本のエレベーターのデザインに即したもの（マイクラ × リアルの融合）
- **寸法**：実機資料の1.5倍スケール（プレイヤーの体格に合わせるため）
- **方針**：基本はリアル志向。ただし動力や設置まわりはマイクラらしいパワープレイを許容する

## 開発環境と構成

NeoForge・Minecraft 1.21.1で開発し、Minecraftに依存しないロジックを`core`モジュールとして分離する。

MOD名は**Real Elevator**、mod idは`realelevator`とする。

| 項目 | 決定内容 |
| --- | --- |
| ローダー | NeoForge |
| 対象バージョン | 1.21.1（以降のバージョンにも順次展開） |
| 言語 | Java |
| ビルド | Gradleマルチモジュール |

**モジュール構成**

- `core`（純粋なJava、MC非依存、JUnitでテストする）
  - 運転曲線（S字加減速、時刻から位置を求める関数）
  - 運行制御（呼びの登録、2度押しキャンセル、乗合全自動、将来の群管理）
  - ドアの状態遷移（反転、強制戸閉、開放待機時間）
  - アナウンスのテンプレートと音声Providerのインターフェース、VOICEVOXクライアント
- `neoforge-1.21.1`（MC依存の薄い層）
  - エンティティ、ブロック、描画、Mixin、ネットワーク、サウンド再生
  - `core`のクラスはMODのjarに同梱し、開発時の起動でも同じMODとして読み込む。
- MOD共通の値（mod id、バージョンなど）はルートの`gradle.properties`、Minecraft・NeoForge・Parchmentのバージョンは各バージョンのモジュールの`gradle.properties`に置く。
- パッケージは`net.lausiv1024.realelevator`。`core`は`net.lausiv1024.realelevator.core`以下に置く。

**多バージョン展開**

- 対応バージョンが増えた段階で、Stonecutter（プリプロセッサ方式）の導入を検討する。
- 1.21.2前後でエンティティの描画がRenderStateベースに変わる見込みのため、レンダラーは書き直しを前提とする。
- Mixinは最小限にし、1クラスに集約する。

## 寸法

JIS A 4301の乗用エレベーターを基準に1.5倍し、ドット格子を揃えるため1/16ブロック（1px）単位に丸める。

| P-9 かご内 幅×奥行 | 1400×1100 | 2.1×1.65 | 2.125×1.625 / 34×26 |
| P-11 かご内 幅×奥行 | 1400×1350 | 2.1×2.025 | 2.125×2.0 / 34×32 |

| P-15 かご内 幅×奥行 | 1600×1500 | 2.4×2.25 | 2.375×2.25 / 38×36 |
| P-17 かご内 幅×奥行 | 1800×1500 | 2.7×2.25 | 2.75×2.25 / 44×36（※2） |
| P-20 かご内 幅×奥行 | 1800×1700 | 2.7×2.55 | 2.75×2.5 / 44×40（※2） |

| P-27 かご内 幅×奥行（※3） | 2000×1900 | 3.0×2.85 | 3.0×2.875 / 48×46（※2） |
| P-30 かご内 幅×奥行（※3） | 2000×2050 | 3.0×3.075 | 3.0×3.125 / 48×50（※2） |
| 出入口幅（P-6・P-9・P-11） | 800 | 1.2 | 1.25 / 20（※） |

- 1ブロック＝1mとして換算する。かご内法と出入口幅は、JIS A 4301の乗用エレベーターの値（三菱電機ビルソリューションズの「エレベーターのかご及び昇降路寸法」、建築士の塾の寸法表）で確認した。
- 以前は P-6 の寸法を「P-9」、P-9 の寸法を「P-11」と呼んでいた（1つずれていた）ので、JISに合わせて直した。
- ※2 P-17・P-20の幅（43.2px）、P-20の奥行き（40.8px）、P-27の奥行き（45.6px）、P-30の奥行き（49.2px）は、かごの中心を1pxの格子にそろえるため偶数に丸める。
- ※3 P-27・P-30はJISにない、各メーカーのオーダー型の寸法（東芝エレベータ「エルクルーズ」の寸法表で確認）。38人乗りなど、さらに大きい機種は寸法が確かめられないので見送る。
- ※ P-6・P-9・P-11の出入口幅は、丸めると19pxになるが、中央開きの戸を同じ幅の2枚（10pxずつ）に分けられるよう20pxにする（実機換算 約833mm）。左右の袖壁は7pxずつになる。
- かごは端数を含む寸法になるため、ブロックの組み合わせではなく独自モデルと独自当たり判定を持つエンティティとして実装する。
- ピット深さと頂部すき間は「リアル寸法／省スペース」を選択できるようにする。
- かごの厚みは、壁1px・床2px・天井2pxとする（実機の概算を1.5倍して丸めた値）。表の寸法は内法で、外形はこの分だけ大きくなる。
- 出入口は正面の袖壁の中央に置く。

**大型の機種**（P-15・P-17・P-20・P-24・P-27・P-30）

- 昇降路の幅は、P-6〜P-15が3ブロック、P-17以上が4ブロック（実機の昇降路の幅2350〜2650mmの1.5倍、約3.5〜4.0ブロック）。かごの外形の幅が45px以上になり、幅3ブロックではロープとレールが収まらないため。
- 幅4ブロックの昇降路では、かごの中心（出入口の中心）がブロックの境目に来る。乗場の三方枠も幅4ブロックにし、出入口はその中央に置く。設置用ブロックは今と同じく三方枠の右隣に置く。
- 横落とし（展望仕様・二方向出入口）では、さらに重りの列の1ブロックが足される。
- 昇降路の幅は `CarModel#shaftWidth`、列の範囲は `ShaftLayout#leftColumn`〜`rightColumn`、三方枠の幅は `DoorGeometry#landingFrameHalfWidth` で求める。

## 移動方式と運転曲線

かごはエンティティとして実際に昇降させ、プレイヤーが普通のブロックの上に立っているのと同じ感覚で運ぶ。

**速度仕様**（実機の速度×1.5）

| 仕様 | 実機 (m/min) | MOD (m/s) | 1tickあたり (ブロック) |
| --- | --- | --- | --- |
| 普通（低） | 60 | 1.5 | 0.075 |
| 普通（高） | 105 | 2.6（2.625を丸める） | 0.13 |
| 高速 | 300 | 7.5 | 0.375 |
| 超高速 | 600 | 15 | 0.75 |

- 加速度も1.5倍とし、約1.5 m/s²を基準にする。
- ジャークも実機値（約1.0 m/s³）の1.5倍とし、1.5 m/s³を基準にする。実機のジャークは0.7〜1.4 m/s³程度。高速仕様（高速・超高速）は標準で2.0 m/s³とする（試行値）。
- 加減速はジャーク制限付きのS字曲線にする。
- 高速仕様は、加速度とジャークを設定で上げられるようにする。短い行程では最高速度に届かないため（例：Y64→−59の約123ブロックでは超高速でも片道約18秒。ジャーク2.0を含めると約19秒）。
  - 上限は実機の高速機の上限付近を1.5倍した値で、加速度2.0、ジャーク3.0とする。下限は標準の値（加速度1.5、ジャーク2.0）で、0.1刻み（`SpeedSetting`）。
  - 普通仕様の加速度とジャークは標準の値に固定する。
  - 発車情報には、速度の仕様ではなく上限値（最高速度・最大加速度・最大ジャーク）を入れて送る。
- 到着時には、床面を階のY座標にぴったり合わせる「着床」処理を行う。

**運転曲線の実装**（`core`の`TravelCurve`／`TravelLimits`）

- 単位はブロックと秒。上限値は最高速度・最大加速度・最大ジャークの3つ（`TravelLimits`）。
- 速度の仕様は`SpeedSpec`（普通（低）／普通（高）／高速／超高速）で、標準の加速度とジャークを持つ。
- 停止から停止までの7区間のS字曲線（ジャーク＋／加速度一定／ジャーク−／定速／ジャーク−／加速度一定／ジャーク＋）。減速側は加速側の鏡像として計算する。
- 行程が短い場合は、最高速度に届かない曲線（定速なし）、さらに短い場合は最大加速度にも届かない曲線に自動で切り替える。
- 時刻から位置・速度・加速度を閉じた式で求める。tick数（partialTick込み）からも求められる（20tick＝1秒）。
- 到着時刻以降は行先の位置をそのまま返し、これを着床とする。

**同期と運搬**

- **決定論的な運転曲線**：サーバーは発車情報（開始tick、出発階、行先階、曲線のパラメータ）だけを送る。クライアントは同じ曲線から位置を計算し、partialTickで描画する。バニラのエンティティ補間による遅延を避けるため。
- **プレイヤーの運搬**：ローカルプレイヤーの移動処理の直前に、かごの移動量をクライアント側で加算する。
- **サーバー側の検証**：サーバーでも同じ曲線でかごの移動量を加味し、「moved wrongly」による巻き戻しを防ぐ。
- **当たり判定**：床・壁・天井・扉の形状を独自のVoxelShapeとして定義し、Mixinでエンティティ衝突の収集処理に差し込む。onGroundが正しく立つので、落下ダメージの問題は起きない。
- **飛行キック**：バニラの浮遊判定は足元のブロックしか見ないため、かごの下が空間だとキックされる。かごの中にいるプレイヤーは、浮遊時間をサーバー側でリセットする（アクセストランスフォーマーを使う）。サーバーにあるプレイヤーの位置は通信の遅れの分だけ古く、上昇中は床より下に見えるので、直近2秒（40tick）のかごの位置のどこかに乗っていればよいとする。ボートなどに乗っているときは、乗り物の浮遊時間もリセットする。
- **サーバーからの位置で動くエンティティ**：モブ、操縦者のいないボート、ほかのプレイヤーなどは、サーバーで運搬する。クライアントでは届く位置が遅れて上昇中に沈み、下降中に浮いて見えるので、地面に立っているものは、かごが走っているあいだと止まった直後（10tick）、描画のためにかごの当たり判定の面に合わせる（`ElevatorCarEntity#restingSurface`）。
- **操縦者が決める乗り物**：プレイヤーが操縦している乗り物は、プレイヤーと同じくクライアントで運搬し、サーバーでは動かさない。止まっているかごでも、床にごく浅く（0.05ブロックまで）入り込んだものは床の上へ戻す（プレイヤーがボートに乗った直後は、サーバーから届いた位置の丸めの分だけ床より下にいることがあり、そのまま動かすとすり抜ける）。
- 昇降は同じチャンク列の中で完結するため、高速でもチャンク読み込みの問題は起きにくい。

**実装メモ**

- かごの位置、当たり判定、運搬量は、すべてゲーム時刻から運転曲線で求める。かごと乗っているエンティティのどちらが先にtickしても、同じ位置になる。
- クライアントでは、ゲーム時刻の代わりに、なめらかに進む時計（`ElevatorClock`）でかごの位置・当たり判定・運搬量・描画を求める。クライアントのゲーム時刻はサーバーから1秒ごとに届く時刻で上書きされ、サーバーが少しでも遅れると1〜2tick巻き戻るので、そのまま使うと走行中にかごと乗っているプレイヤーがまとめて上下に跳ねる（速いほど大きい）。時計は毎tick 1ずつ進め（一時停止中は止める）、ゲーム時刻とのずれを1tickあたり最大0.2tickずつ寄せる。ずれが20tickを超えたら（ワールドに入った直後など）そのまま合わせる。
- 運搬するのは、クライアントではローカルプレイヤー、サーバーではプレイヤー以外のエンティティ。かごの外形の真上か中にいるものを運ぶ。
- 運搬量は「1tick分の移動量」ではなく、前のtickからかごが実際に動いた量とする。クライアントのゲーム時刻はサーバーの時刻に合わせて数tick飛んだり戻ったりするので、1tick分の量だと高速走行で床の中に取り残され、下へ抜け落ちる。
- 念のため、走行中のかごの床や屋根に足が入り込んだエンティティ（深さ1ブロックまで）は、その上面へ押し上げる。
- 到着したtickの移動量も運べるよう、サーバーは走行情報を到着の1tick後に消す。
- 発車情報はエンティティの同期データで送る。保存時に走行中だった場合は、ゲーム時刻に合わせて続きから走る。

## 昇降路の機構と描画

防犯窓や展望ガラス越しに見えるよう、巻上機・シーブ・ロープ・釣合い重りをかごの動きと連動させて描画する（必須要件）。

かごと釣合い重りはロープで直接引かず、シーブをかませて動滑車のように吊る。

**構成（機械室レス、2:1ローピング）**

```
  ロープ端(固定)                        ロープ端(固定)
  ═╤══════════════════════════════════════╤═  ← 昇降路頂部
   │                    (巻上機)          │
   │                   ╭─────╮            │
   │                   │  ●  │            │
   │                   │     │            │
   │   ┌───────────┐   │     ╰──(シーブ)──╯
   │   │           │   │        ┌──┐
   │   │    かご    │   │        │CW│  ← 釣合い重り
   │   │           │   │        └──┘
   │   └───────────┘   │
   ╰─(シーブ)────(シーブ)─╯   ← かご下シーブ
```

- 巻上機：昇降路の頂部に設置する。
- かご側：かごの下部にシーブを付け、ロープをかごの下にくぐらせる。
- 釣合い重り側：釣合い重りの上部にシーブを付ける。
- ロープの両端は昇降路の頂部に固定する。
- 昇降路の寸法には、釣合い重りとそのレールの分も含める。

**運動の関係**

- 釣合い重りは、かごと逆向きに同じ速さで動く。
- 2:1ローピングのため、巻上機の綱車の周速はかごの速度の2倍になる。
- 各シーブは、ロープの動きと半径から回転角を求めて回す。

**描画**

- かごと同じ運転曲線から、釣合い重りの位置、各シーブの回転角、ロープの長さを計算する。そのため追加の同期は不要。
- ロープは、固定点とシーブの接点を結ぶ区間ごとの線として描く。
- 見えていないときは、距離やカリングで描画を省略する。
- 細部はCodeで作業しながら決める。

**実装**（`core`の`HoistMechanism`）

- ウィザード設置の昇降路は幅3ブロックで、かごの左右のすき間は0.25〜0.375ブロックしかないため、釣合い重りは上の図と違い、かごの奥の列に置く。
- ロープの経路（乗場から見て）：左上の固定端 → かごの左側のすき間を下りる → かご下の2つのシーブで左から右へくぐる → 右側のすき間を上る → 頂部のそらせ車で奥へ向きを変え、天井の1px下を水平に通る → 頂部の奥右にある巻上機の綱車 → 奥の釣合い重りの上のシーブ → 頂部の固定端。
- かご側のシーブ・固定端・左右のロープは、かごが傾かないよう、かごの奥行きの中央に置く。ロープはどの区間も垂直か水平になる（シーブの軸が変わるところで、並びが少しずれるだけ）。
- ロープは3本で、太さ1px、間隔2px。そのとき巻き付いているシーブの軸の方向に並べる。かごの横のすき間が4pxしかないP-13では、そらせ車と綱車をすき間に収めるため、間隔を1.5px、シーブの幅を4pxにする。
- シーブの半径（ロープの中心が通る半径）は、かご下4px、そらせ車と巻上機の綱車5px（そらせ車はかごの横のすき間の上にあるので、かごには当たらない）、釣合い重り6px。幅は6px。巻上機のモーターは綱車と同じ軸で、綱車の内側に置く。
- 釣合い重りは幅14px・厚み6px・高さ40px（2.5ブロック）。レールは重りの奥の両端に置く。かごが最上階にいるとき、重りの下面はピットの底から8px上（ランバイ）。この寸法で、省スペースのピット（1＋4）でも、かご・重り・巻上機がぶつからない。
- 当たり判定は釣合い重りだけに付ける（ロープは細いので付けない）。
- かご側のロープ・シーブ・固定端は奥行きの中央に置くが、ガイドレールの列が中央の近くにある機種（P-6・P-11・P-15・P-17・P-20・P-24）では、レールに当たらないよう、レールと反対の向きへずらす（6pxまで）。
- 右のガイドレールは、そらせ車と重ならないよう天井の1ブロック下で止める（P-13はレールがかごの中央より奥にあり、そらせ車と重なるため。全機種で同じ扱い）。
- 機構はウィザードで設置したかごだけが持つ（デバッグコマンドで出したかごには付かない）。かごがピットの方式を同期データで持ち、描画も当たり判定もかごの運転曲線から求める。
- **横落とし**：釣合い重りをかごの右側（乗場から見て、設置用ブロックの側）に置く配置。設置用ブロックの設定画面で「釣合い重り：後ろ落とし／横落とし」を選べる（実機でも普通の乗用に横落としがある）。展望仕様（奥の重りが景色をふさぐ）と二方向出入口では横落としに固定する（それぞれを作るときに）。
  - 重りの列は、設置用ブロックの真後ろの列（乗場の壁の列より奥）。かご・三方枠・設置用ブロックの位置は後ろ落としと同じで、昇降路はかごの幅（3または4ブロック）に重りの1列を足した幅になる。奥行きはかごの分だけ（奥の重りの列はいらない）。
  - かご側のロープは後ろ落としと同じ（左上の固定端 → かご下の2つのシーブ → 右側のすき間を上る）。巻上機は右上に置いて綱車の軸を前後（Z）向きにし、綱車はかごの右のすき間と重りの列の中心のあいだにかかる。ロープは綱車を越えて重りの列へ下り、重りの上のシーブ（軸は左右）を前から後ろへくぐって頂部の固定端に戻る。そらせ車はいらない。モーターは綱車の手前に置く。
  - 重りは前後に広い（幅14px・厚み6px）。重りのレールは、後ろ落としと同じく重りの背面（右の壁の側）の前後の両端に沿わせる。重りのシーブに出入りするロープは重りの厚みの中を通るので、レールとは重ならない。
  - ガラスにするのはかごの奥壁だけなので、横の重りは景色にかからない。
  - 頂部の制御盤は、昇降路の左の壁（重りの列と反対側）の上部に、奥寄りに付ける（奥の壁に置くと景色にかかるため）。左の壁のすき間はかご側のロープとガイドレールも通るので、それを避けたいちばん奥の列にする。
- 描画は、色を付けた仮の箱・多角柱・棒で行う。シーブの側面には暗い扇形を入れ、回っているのがわかるようにする。素材はデザインシステムで差し替える。

**かごの外側とガイド**（フェーズ4-6）

- **素材感**：かごの外側は亜鉛メッキ調の灰色（オリジナルのドット絵）。かご枠や金具は少し暗い塗装色。
- **ガイドレール**：断面をT形に描き直す。壁側のフランジ（4px×1px）に、かごに向かう刃（厚み1px×長さ3px）を付け、当たり判定もT形にする。壁への取り付け金具（ブラケット）もところどころに描く。
- **ローラーガイド**：たて枠の上と下、左右のレールごとに、箱に入った3つのローラー（半径1.5px くらいの円盤）を付ける。左右の2つは刃の両面に、残り1つは刃の先端に当てる。シーブと同じく運転曲線から回転角を求めて回す（追加の同期はいらない）。
- **かご枠**：たて枠・上はり・下はり。下はりは、かご下のシーブとロープにぶつからない形にする。
- **ドアオペレーター**：かご上の出入口の上に箱とモーターを置き、戸の開き具合に合わせてベルトを動かす（二方向出入口では奥にも）。
- **エプロンと非常止め**：出入口の下に垂れる板（エプロン）と、たて枠の下の非常止め装置。エプロンはピットの底や乗場の床にぶつからない長さにする。
- **かご上の安全柵**：かごの屋根の縁の手すり。かごの上に乗ったときの当たり判定も付ける（ロープ・シーブ・レールとぶつからない位置にする）。
- **実装**（`core`の`CarFrame`。`HoistMechanism#carFrame`）
  - 機器はウィザードで設置したかごだけが持つ（昇降路の機構と同じ）。描画は昇降路の機構と同じく、それぞれの場所の明るさで描く。
  - かごのすき間（外壁からレールの先端まで）は、P-6・P-9・P-11 が2px、P-13・P-15 が0px、P-17・P-20 が5px、P-24以上が3px。
  - ガイドレール：ブロックのかごと反対側の端に、フランジ（奥行き4px×厚み1px）と刃（厚み1px×長さ3px、厚みの中心がブロックの中央）。当たり判定も T 形。取り付け金具は、ピットの底から3ブロックおきに、フランジの外側（かごのローラーが通る範囲の外）で壁に付ける。
  - かご枠：たて枠・上はり（屋根の上の3px）・下はり（床の下の3px）を、レールと同じ奥行きの位置に幅3pxで通す。たて枠は、すき間が1px以上あればその中に1pxの柱として、なければ外壁の厚みの外側の半分（0.5px）に埋めて描く（内側の面と重ねると、かごの中からちらついて見える）。暗い塗装色。かご下のシーブの金具とロープはレールから奥行きの向きに離れているので、ぶつからない。
  - ローラーガイド：上はりの上と下はりの下に、台の板（刃のところは切り欠く）と3つのローラー。ローラーの半径は1px（1.5pxではP-13で横のすき間のロープに当たるため）。刃の両面に2つ、先端に1つ当て、かごの位置から回転角を求めて回す。
  - 非常止め：下のローラーガイドの下に、刃を両側から挟む形。
  - ドアオペレーター：屋根の上の出入口の側に、戸の動く範囲いっぱい（ただし安全柵にかからないよう外壁の1px内側まで）の、奥行き4px・高さ4pxの箱（上はりが近い機種では、上はりの手前で止める）と、右端の3pxのモーター。箱の前の面にベルトを描き、戸板ごとの吊り金具が戸と一緒に動く（ベルトの端で止まる）。二方向出入口では奥にも。
  - エプロン：出入口の幅で、かごの戸の外側の面に沿って床の下に垂れる、亜鉛メッキ調の板。長さは18pxで、ピットの底に1pxの余裕を残して収まらなければ短くする（省スペースのピットでは13px）。二方向出入口では奥にも。
  - 安全柵：屋根の縁の、出入口の側を除く3辺（二方向出入口では左右の2辺）。黄色の柱（8px以内おき）と、上と中ほどの横棒。高さは11pxで、かごが最上階にいるとき頂部の天井に1pxの余裕を残して収まらなければ低くする（省スペースでは6px）。左右の辺は、ローラーガイドと上はりのところ（レールの前後3px）で切る。当たり判定を持つ。
  - かごの外側の面：かごの部位の各面のうち、かごの外を向く面（面の少し外側の点がかごの外形の外にある面）は、亜鉛メッキ調のテクスチャ（`tools/textures/make_exterior.py`）で、まわりの明るさで描く。かごの中を向く面は今までどおり内装の素材とかご内の明るさ。戸板も、外を向く面はまわりの明るさにする（戸板は袖壁の外のレールを通るので、戸の動く範囲までをかごの内側として面を分ける。4枚戸の中の2枚が暗くならないように）。
  - 戸の上の張り出し：出入口の上（戸の上端から上）で、かごはトランサムの下面を、乗場は三方枠の上の部分の下面を、閉じた戸板の上でその戸板の奥行きまで張り出す（外のレールを通る戸、たとえば4枚戸の中の2枚や片開きの速い戸の上では深くなる）。素材はかごがトランサム、乗場が枠と同じ。幅は出入口の幅で、戸板の重なるところは深い方にそろえる。かごは前壁の外面から、天井の上面の高さまで。乗場は三方枠の裏まで、枠と同じ高さ4px。戸の上や戸のあいだから昇降路が見えないようにする（`DoorGeometry#soffits`）。
  - 戸当たり：片開き（2S）では、閉じたときに戸袋と反対側の縁を覆うのは外のレールの戸だけなので、袖壁（乗場は三方枠）とのあいだにレール1本分のすき間が縦に残る。その縁の外に、袖壁（三方枠）から戸の動く範囲の奥行きまで伸びる、幅1px・戸の高さの板を付けて埋める（`DoorGeometry#jambReturns`。素材はかごが前壁、乗場が枠）。
  - 乗場の三方枠の範囲の壁は、昇降路の側（裏）の面と、三方枠の範囲の外周（左右の端・上端・下端）の面も描く。

## 運行制御と操作方法

操作方法は日本式エレベーターに合わせ、制御方式は乗合全自動を基本とする。

**乗場**

- ▲▼ボタン
- 階床表示器
- ホールランタンと到着チャイム

**かご内**

- かご操作盤は正面（ドアがある面）の袖壁に、ドアの横に並べて配置するのを基本とする。行先ボタンは2列配置
- ▶◀（閉）／◀▶（開）ボタン
- インターホン
- 2度押しで行先をキャンセルする機能
- 車椅子用操作盤（低い位置に設置し、押すと戸開時間を延長する）

**車椅子用操作盤の実装**（`core`の`ButtonLayout#wheelchairPanel`／`WheelchairCalls`）

- 設置用ブロックとリニューアルの設定画面の「車椅子用操作盤」でオン／オフを選ぶ（既定はオフ）。オンにすると、かごの左右両方の側壁と、各階の乗場に車椅子用のボタンが付く。
- かごの車椅子用操作盤は、側壁の内面の奥行きの中ほどに横長に置く。扉の側の端の列に開（下）・閉（上）を置き、そこから奥へ、各列の下の段から順に行先ボタンを並べる。2段を基本とし、奥行き（両端に2pxずつ空ける）に収まらなければ段を増やす。いちばん下の段の下端は21px（実機 約900mm）。
- 乗場の車椅子用ボタンは、▲▼の下に、車椅子マークをはさんで同じ並びで置く（高さは「乗場の実装」を参照）。
- 車椅子用のボタンの色は、車椅子マークの代わりの仮の青。マークはデザインシステムで付ける。
- 車椅子用のボタンで登録した呼びは、運行では普通の呼びと同じに扱う。応答灯は、かごも乗場も同じ扱いで、車椅子用のボタンで押すと普通のボタンと車椅子用のボタンの両方が点き、普通のボタンで押しただけなら車椅子用は点かない（あとから車椅子用を押せば、車椅子用の呼びになって点く）。
- 車椅子用のボタンで登録した呼びに応えて開いたとき、車椅子用操作盤の開ボタンで開いたとき、かごのいる階で車椅子用のボタンを押して開いたときは、開放待機を10秒に延ばし、閉じるのを1.5倍の時間（約3.8秒）にしてゆっくり閉じる。閉まりきるまでは、普通のボタンで開き直しても短くならない。
- 二方向出入口では、車椅子用操作盤の行先ボタンは、最後に開いた扉の反対側の扉を開く（車椅子はかごの中で向きを変えられないため）。その階に反対側の出入口がなければ、その階にある扉を開く。

**制御**

- 乗合全自動：呼びを進行方向順に処理する。
- **複数台の群管理**（フェーズ5-2。`core`の`GroupDispatcher`、`ElevatorGroups`）
  - 群は保守用レンチでつなぐ。しゃがみながらレンチで群のエレベーターの乗場を右クリックして選び（レンチに覚える）、別のエレベーターの乗場をレンチで右クリックして開くメニューの「群に入れる」で、選んだエレベーターと同じ群にする（選んだほうが群に入っていなければ、2台で新しい群を作る。入れるほうがほかの群に入っていれば、そこから外す）。「群から外す」で外す。残りが1台になった群はなくす。メニューの見出しに群の台数を出す。
  - 群は最大8台。同じディメンションの、水平に32ブロック以内のかご。停止階はかごごとに違ってよい。
  - 群のどの乗場で押した乗場呼びも、その階（同じY）に止まるかごのうち、着くまでの時間の見積もりがいちばん短いかごに割り当て、そのかごの呼びとして登録する。割り当てたら変えない。休止中のかごには割り当てない。すでに群のどれかのかごに同じ階・同じ向きの呼びがあれば、そのかごの呼びとして押す。
  - 見積もり：かごが今の進行方向に、止まる予定の階（かご呼び・乗場呼びのある階）に順に止まりながら進み、その向きの最後の呼びで折り返すとして、走る距離を最高速度で割った時間に、止まる回数ごとに10秒、走り出しに2秒、戸が開いていれば6秒を足す。呼びと同じ向きに進んでいて、呼びの階がまだ先にあれば、その途中で止まる。
  - 即時予報：割り当てたらすぐ、そのかごのその階のホールランタンの、呼びの向きの段を点滅させずに点け、G#5 の単音（上りも下りも同じ。`tools/sounds/make_chime.py` の `chime_forecast`）を鳴らす（チャイムの設定がオンのとき）。到着したときは、今までどおりの2音の到着チャイム。到着すると今までどおり点滅に変わる。
  - 乗場のボタンの応答灯は、群のどれかのかごにその階・その向きの呼びがあれば、群のすべての乗場で点く（車椅子用も同じ）。
  - 群のほかのかごに割り当てたときは、そのかごのその階の正面（なければ奥）の扉を開く。
  - 群はかごが持ち（保存し、クライアントへも同期する）、読み込まれているかごだけで割り当てる。
- ボタンは操作盤上のボタン単位で当たり判定を持たせ、レイキャストで押下を判定する。

**ボタンと運行制御の実装**（`core`の`CollectiveControl`／`ButtonLayout`）

- ボタンは2px角で、取り付け面から1px出っ張る。右クリックで押し、視線の先をボタン1つずつの箱でレイキャストする。ブロックより手前にあるときだけ押せ、届く距離はブロックと同じ。
- かごの操作盤は、かごの中から扉の方を向いて右側の袖壁に置く。設定で両側の袖壁に置くこともできる（左右とも同じ並びで、どちらのボタンでも同じ呼びになる）。行先ボタンは2列で、下の段から順に左の列に奇数階、右の列に偶数階を並べ、その下の段に開・閉ボタンを置く。
- 乗場の▲▼ボタンは乗場の扉のエンティティが持ち、乗場から見て出入口の右側の操作盤（壁付けの板、または幅広の右の枠。「乗場の実装」を参照）に置く。戸袋は三方枠の裏にあるので、脇の面のどこにでも付けられる。最上階は▼だけ、最下階は▲だけ。
- 登録された呼びのボタンは応答灯がつき、応えると消える。
- 乗合全自動は、進行方向にある呼びを近い順に処理する。上昇中はかご呼びと上りの乗場呼びの階に止まり、その先に止まる階がなければ最も上の下りの乗場呼びまで行って反転する（下降中も同様）。
- 停止中で方向が決まっていないときに呼びが登録されたら、戸が開いていてもその場で呼びの方へ方向を決める（方向灯をすぐにつける）。
- 戸が閉まって発車を決めてから、0.5秒遅れて動き始める（実機の起動にかかる時間を模す）。その間に戸が開き直したら発車を取りやめる。
- かごが止まっている階の呼びは、登録せずにその場で戸を開く。ただし進行方向と逆の乗場呼びは、進行方向の先に呼びが残っていれば登録して後で応える。
- 乗場呼びに応えたときは開放待機を乗場呼びの長さに、かご呼びだけなら短い方にする。
- 走行中に、行先より手前の階にかご呼びか進行方向の乗場呼びが登録されたら、減速が間に合う限りその階に止まる。間に合わなければ通過し、呼びは残して後で応える。
  - 判定：運転曲線は加速をできるだけ長く続けてから減速する形なので、出発時点から途中階まで改めて計画した曲線が、今の位置・速度・加速度と一致していれば減速が間に合う。
  - 止まる場合は、発車情報の行先だけを差し替える（出発時刻と出発位置は同じ）。位置は途切れずにつながり、送るものも発車情報のままでよい。
- **2度押しキャンセル**（`CollectiveControl#cancelCar`／`CancelReplan`）
  - 応答灯の点いた行先ボタンを、0.5秒（10tick）以内に2回続けて押すと、その行先を取り消す。登録した押下は数えないので、点いていないボタンを素早く2回押しても取り消さない。取り消せるのはかご呼び（普通の操作盤・車椅子用操作盤）だけで、乗場呼びは取り消せない。
  - 使用キーを押したままの繰り返しでは、ボタンを押さない（押しっぱなしで取り消さないように）。
  - 二方向出入口では、押した側の操作盤の呼びだけを取り消す。反対側の操作盤でも登録されていれば、その階には止まる。車椅子用操作盤で取り消すと、両側の呼びを取り消す。
  - 走行中に今向かっている階の呼びを取り消したとき：その階にほかの呼び（乗場呼びなど）が残っていればそのまま止まる。その先に止まる階があり、まだ減速を始めていなければ、行先をその階へ延ばす（出発時点から計画し直した曲線が今の状態と一致するときだけ。短い走行は最初から形が違うので延ばせないことがある）。延ばせなければ、その階に止まるが戸は開けずに次へ向かう。呼びが1つもなくなったら、止まれる最寄りの階に止まり、戸は開けずに待つ。
  - 取り消した階の到着チャイムとホールランタンはやめる。

**階床表示の実装**（`core`の`FloorIndicator`／`DotFont`）

- 表示は階名と進行方向の矢印。ドットで描く（既定）ときは階名3文字まで、フォントで描くときは4文字まで（下の「表示の文字」）。1ドット＝1pxのドットマトリクスで、文字は3×5ドット、矢印は5×5ドット。点灯色は既定でアンバー（「表示器の色」で選べる）。
  - 3文字の階名（「MB1」など）：停止階に3文字の階名があるエレベーターでは、1px のドットの表示器（乗場の扉の上、かごのトランサム）を4px広げ（乗場の扉の上は20×7px）、乗場の壁付けの操作盤は板と表示窓を2px広げる。0.5px のドットで 5×7 の文字を使う表示器（主操作盤、車椅子用操作盤）は、3文字の階名だけ 3×5 の文字で出す。ドットで出すのは、ドットにある文字だけを先頭から3文字まで（漢字などは出さない。設定画面の停止階の欄で知らせる）。
  - 表示窓の中の矢印と階名は、ドットの並びの端数を含めてちょうど中央に置く（0.5px のドットの表示器では半ドットずらすことがある）。
  - **表示の文字**：設置用ブロックとリニューアルの設定画面の「表示の文字」で、ドット（既定）とフォントを選ぶ（エレベーターごと。仕様書にも入る）。フォントでは、階床表示器と行先ボタンの階名をゲームのフォントで描き、漢字なども出せる。表示器の階名の欄やボタンの面に収まるよう縮め、中央に置く（矢印はドットのまま）。表示器の色で光らせる。フォントはこのMOD専用の `realelevator:indicator`（バニラの英数字と Unifont を参照する）で、バニラのフォントを差し替えるリソースパックの影響を受けにくくする（このフォントを差し替えれば、表示器の字だけを変えられる）。1ブロック＝16pxの原則の例外。フォントでは、3文字の階名のために表示器を広げない。
  - **光るものの明るさ**：表示器のドット、点灯した応答灯の図柄、点灯したホールランタンは、まわりの明るさによらず最大の明るさで描き、面の向きによる陰も付けない（LEDなどの光で表示するものなので。フォントで描く文字と同じ明るさになる）。
  - **浮かぶ階名**：行先ボタンに視線を合わせたとき、階名が3文字以上なら、ネームタグのようにボタンの上へ階名を浮かべる（ドットとフォントのどちらでも）。
- 並べ方は、横長（矢印、階名の順。14×5px）と縦長（上に矢印、下に階名。7×11px）の2通り。
- 表示器の位置は選べる。初期値は日本の標準仕様に合わせ、乗場はボタンの上（三方枠の横）、かごは右側の操作盤の上。
  - 乗場・扉の上：出入口の上の中央に横長で、ふち1px（16×7px）。出入口から1px上。
  - 乗場・ボタンの上：乗場の操作盤の上部の表示窓に縦長（「乗場の実装」を参照）。群管理向けの設定では、乗場の表示器を付けない。
  - かご・扉の上：出入口の上のトランサム（高さ5px）に、横長でふちなしで埋め込む。
  - かご・操作盤の上：操作盤の袖壁の行先ボタンより上に縦長。操作盤が両側のときは、左側にも付けるかを選べる。
- 乗場の表示器は乗場の扉のエンティティが持つ。
- 停止階の間隔が5ブロック未満の階があると、上の階の床が三方枠の一番上の段の前に来て、出入口の上の器具を隠してしまう。そのため、その場合は乗場の表示器とランタンの「扉の上」を選べなくし、選ばれていれば横（表示器はボタンの上、ランタンは扉の横）へ移す。
- 乗場のボタン・表示器・ホールランタンは、どの配置でも三方枠の面（幅3ブロック、高さ4ブロック）に収め、出入口の前にはかけない。扉の上に表示器とランタンを重ねられるのは幕板付きのときだけで、すき間を1pxにして三方枠の高さに収める（細枠では枠の上に10pxしか残らないので、表示器が扉の上ならランタンは扉の上を選べず、扉の横へ移す）。
- 表示器と操作盤の配置は、設置用ブロックの設定画面と保守用レンチのメニューで選ぶ（デバッグ用コマンドでも変えられる）。
- 表示する階は、かごの位置に最も近い停止階（階と階の中間を過ぎると切り替わる）。かごの位置から各クライアントで求めるので、追加の同期はいらない。
- 長い階間（間隔が10ブロック以上。急行区間など）では、どちらの停止階からも4ブロック（約1階分）以上離れているあいだ、階名の代わりにハイフン2つ（「--」）を出す。矢印はそのまま出す。かごと乗場の表示器のどちらも同じ。
- 矢印は、走行中はその向き、停止中は次に進む方向が決まっているときだけ出す。
- 階名は、階名を設定する仕組み（ウィザード）ができるまで、下から1、2、3…とする。文字は数字と、B・F・G・L・M・P・R・-に対応する。

**ホールランタンと到着チャイムの実装**（`core`の`HallLantern`）

- ホールランタンは上下2段の棒状のランプで、上の段が上り、下の段が下り。位置は選べ、付けないこともできる。実機では有償の付加仕様なので、初期値は付けない。
  - 扉の上：出入口と同じ幅の横長、各段2px。細枠なら枠の上の壁に、幕板付きなら幕板に付ける。幕板で乗場の階床表示器が扉の上にあるときは、その上に置く。
  - 扉の横：乗場から見て出入口の左（ボタンと反対側）の、枠のすぐ左（1px空ける）の壁に縦長。幅2px、各段7px、段の間1px、高さ37〜52px。最上階と最下階では上下の段をつなげて1本にする。
  - 扉の右：群管理向けの設定のときだけ選べる。操作盤の上に、扉の横と同じ大きさの縦長。
- 到着チャイムと同時に行先階のランタンの点滅を始め、到着して扉が閉まる（全閉になる）まで続ける。点滅は点灯0.75秒・消灯0.5秒を繰り返し、点灯から始まる。中間階では進行方向の段（到着前はチャイムと同じく先読みした方向）、最上階と最下階では両方の段を点ける。中間階で方向が決まっていなければ点けない。止まっている階の乗場呼びに応えて戸を開くときは、その場で点滅を始める。
- 点灯色は階床表示器と同じ（「表示器の色」で選べる）。
- 到着チャイムは実機では有償の付加仕様なので、初期値は鳴らさない（設定で鳴らせる）。鳴らさなくても、ホールランタンはチャイムを鳴らすはずだったタイミングで点滅を始める。ホールランタンを付けないときは、出入口の上の中央から鳴らす。
- 到着チャイムは、上りも下りも2音。上りは G#5 → C6、下りは C6 → G#5 で、2音目は0.45秒後。方向が決まっていないときは上りの音。
- 到着チャイムは、到着が確定していて、なおかつ到着の6秒前を過ぎた時点で、行先階のホールランタンの位置から鳴らす（長い走行で早く鳴りすぎないため）。
  - 到着が確定するのは、行先の1つ手前の階に減速しても止まれなくなったとき（途中階で呼ばれても止まれなくなったとき）。行先が隣の階なら発車した時点で確定する。運転曲線がゆるやかなので、階の間隔が短いと発車してすぐに確定することもあり、そのときは走行が6秒より短ければ発車直後に鳴る。
  - チャイムの向きは、到着したあとの進行方向を、その時点で登録されている呼びから先読みして決める。
  - 止まっている階の乗場呼びに応えて戸を開くときは、その場で鳴らす。
  - 同じ階のチャイムが鳴っているあいだ（2.05秒）は、乗場のボタンを押しても重ねて鳴らさない。
  - かごのいる階で戸が開いている（開きかけ・閉まりかけを含む）あいだに乗場のボタンを押しても、ホールランタンの点滅は始め直さない（戸が閉まっていたときだけ始める）。行先方向のアナウンスも、同じ方向をもう流していれば流さない（戸が閉まりきると流したことを忘れ、閉まったあとに呼んで開いたときは、また1回流す）。到着チャイムは、鳴り終わっていれば押すたびに鳴らす。
- チャイムの音は、実在メーカーの音を使わず、ベルに似た倍音を重ねてプログラムで合成し、OGGで同梱する（`tools/sounds/make_chime.py`）。リソースパックで差し替えられる。

## ドア

ドアは状態遷移で制御し、セーフティシューと多光軸ビームセンサーの両方で反転させる。

**状態遷移**

| 現在の状態 | 条件 | 次の状態 |
| --- | --- | --- |
| 閉 | 呼び | 開動作 |
| 開動作 | 全開 | 開放待機 |
| 開放待機 | 待機時間終了／「閉」ボタン | 閉動作 |
| 開放待機 | 開き始めてから60秒たつ | 強制戸閉 |
| 閉動作 | セーフティシュー／ビームで検知 | 開動作（反転） |
| 閉動作 | 閉まりきるまでに5回反転する | 強制戸閉 |
| 閉動作 | 全閉 | 閉 |
| 強制戸閉 | 全閉 | 閉 |

**検知**

- **セーフティシュー（接触式）**：閉まりかけの戸先にエンティティのAABBが触れたら反転する。
- **多光軸ビームセンサー（非接触式）**：かごの扉と乗場の扉の間に、出入口の全高（約3.125ブロック）にわたる薄い検知領域を置く。閉動作中にエンティティが入ったら反転する。

**開放待機時間**

- 乗場呼びのときは長め、かご呼びのときは短めにする。
- 車椅子用操作盤から呼んだ場合は延長する（10秒。閉じるのもゆっくりにする）。
- 「閉」ボタンで短縮できる。
- **乗場ボタンの押し続け**：かごがその階に止まって、押した側の扉を開けている（開きかけ・閉まりかけを含む）あいだに乗場のボタンを押したままにすると、開ボタンを押したままのときと同じく戸を開けておく。離してから乗場呼びの開放待機（車椅子用のボタンなら車椅子用の時間）がたつと閉める。押したままのあいだは呼びを押し直さないので、チャイムやアナウンスは流さない。強制戸閉の60秒は、開ボタンと同じく数える。
- **開ボタンの押し続け**：押しているあいだは戸を開けたままにする。かご内でしゃがんでいるプレイヤーがいるあいだも、開ボタンを押しているものとして扱う（走行中と強制戸閉中は効かない。クリック音は鳴らさない）。
- **開延長**：設置用ブロックとリニューアルの設定画面の「開延長ボタン」でオン／オフを選ぶ（既定はオフ）。オンにすると、かごの主操作盤に開延長ボタン（開ボタンの下。図柄は ◀|▶ と「＋」）が付く。押すと戸を開き、全開になってから60秒開けておく。
  - 延長中にオフにすると、延長をやめて通常どおり閉める。
  - 延長中はボタンが光る。もう一度押すと60秒を数え直す。閉ボタンで解除する。
  - 延長中は、開ボタンと多光軸ビームで時間を変えず、強制戸閉の60秒も数えない（終わると数え直す）。終わると通常どおり、戸閉アナウンスを流して閉める。
  - 強制戸閉中は受け付けない。車椅子用操作盤には付けない。階床が多くて非常呼びを省くときも付く。

**強制戸閉**

反転が何度も続いた場合、または扉が一定時間（30〜60秒程度）開いたままになっている場合は、ブザーを鳴らしながら低速で強制的に閉める。

- **強制戸閉の実装**（`core`の`DoorController`）
  - 入る条件：閉まりきるまでに続けて5回反転した（セーフティシュー・多光軸ビームの反転を数え、閉まりきると数え直す。5回目の反転はふつうに開き直し、開ききってから強制戸閉で閉め始める）、または開き始めてから閉まりきらないまま60秒たった（ビームの検知や開ボタンの押し続けで開けたままの時間も数える）。
  - 普通の2倍の時間（5秒）をかけて低速で閉める。車椅子用のゆっくり閉じるのより遅いほうにする。戸閉アナウンスは流さない。
  - 強制戸閉中は、多光軸ビームと開く操作（開ボタン、かごのいる階の乗場ボタン・行先ボタン）を受け付けない。かごのいる階で押した乗場ボタンは登録もしないので、閉まったあとに押し直す（反対側の出入口で押された呼びは、今の扉が閉まってから開く）。
  - セーフティシューは効き、開き直すが、開ききったらすぐ（開放待機も戸閉アナウンスも待たずに）また閉め始める。閉まりきるまで強制戸閉を続ける。
  - 強制戸閉中は、かごの中（床から2.5ブロック）でブザーを1秒ごとに0.5秒鳴らす。音は合成したもの（`tools/sounds/make_buzzer.py`）。
  - 強制戸閉中かどうかは戸の状態と一緒に同期し、クライアントも同じ速さで閉まる。

**その他**

- 扉の方式：2枚中央開き（CO）／2枚片開き（2S）／4枚中央開き（4CO）。二方向出入口（前後・直角）にも対応する。
- かごの扉と乗場の扉は連動して動かす。
- 同期はかごと同じく「開始tick＋状態」だけを送り、扉の位置はクライアント側で計算する。

**ランディングオープン**（実装済み）

- 着床の直前、戸開区間に入ったところで戸を開き始め、乗り降りを始められるまでの時間を縮める。
- 設置用ブロックとリニューアルの設定画面でオン／オフを選ぶ。既定はオフ。
- 到着の0.75秒前（15tick前。残り約2px＝実機の戸開区間75mmの1.5倍相当）から開き始める。
- その時点で到着として扱う（呼びの記録を消し、チャイムを鳴らし、今いる階を確定する。開ボタンなども効く）。かごは運転曲線どおりに着床まで動き続ける。
- 乗場の扉は、かごがその階に着いた扱いになった時点から、かごの戸と同じ開き具合で動く。
- 同期は増やさない。戸を開き始める時刻は発車情報（到着tick）から決まるので、サーバーとクライアントがそれぞれ計算する。サーバーが重くても、かごと扉の動きはずれない。
- 開き始めたときの床の段差は最大約2pxで、プレイヤーの段差越えの範囲に収まる。
- 実装：着床の15tick前（`OperationTiming#LANDING_OPEN_TICKS`）になったら、サーバーが行先に着いた扱いにして戸を開く（戸の状態はいつもどおり同期する）。それから着床までのあいだは、呼びと開ボタンについて止まっているとみなす。乗場の扉は、走行中でも行先の階で戸が開き始めていれば一緒に動く（`ElevatorCarEntity#isAtLanding`。クライアントも同期した走行情報と戸の状態から決まる）。
- 休止に切り替えたときの着床と、2度押しキャンセルで戸を開けずに止まるときは、ランディングオープンにしない。

**二方向出入口**（前後は実装済み。直角は未実装）

- 前後（スルー型）と直角（L字）の2つ。直角の横の出入口は、乗場から見て左の側壁だけに開ける。前後を先に作った。直角は後回しにし、左のすき間（ガイドレール・ロープ・頂部の制御盤）の扱いと、横の操作盤が置けない機種（P-9は横の出入口の脇が3px）の扱いを、作るときに決める。
- **前後（スルー型）の実装**
  - 設置用ブロックの設定画面で「二方向出入口（前後）」をオンにし、停止階の欄で階ごとに「前／後／両」を選ぶ。最下階（設置用ブロックの階）は前を必ず使う（「前」か「両」）。
  - 奥の出入口・戸・操作盤・表示器は、正面の形をかごの中心のまわりに180°回したもの（`Entrance#quarterTurns`）。かごの奥壁は、正面の袖壁とトランサムを180°回したものに置き換える。
  - 奥の乗場の戸の位置はブロックの格子にそろわないので、正面と同じ決め方（戸のかご側の面より乗場側で、昇降路側の面がいちばん近い列）で奥の乗場の壁の列を決め、奥の三方枠を厚くしてその列の乗場側の面まで埋める（`ShaftLayout#rearWallRow`／`rearFaceOffset`）。奥の乗場のボタン・表示器・ランタンは、その厚くした三方枠の面に付く。
  - 昇降路は奥の乗場の壁の列の手前まで延び、釣合い重りは横落としに決まる。設置では、奥を使う階にだけ奥の三方枠の場所を空ける必要がある。
  - 呼びは乗場もかごも側ごとに分ける（`EntranceCalls`）。乗場の呼びは押した乗場の側、行先ボタンと開ボタンは押した操作盤の側の扉を開き、押した側のボタンだけ点く。その階に押した側の出入口がなければ、その階にある扉を開く。
  - 両側の扉が同時に開くことはない。同じ階で両側に呼びがあるときは、先に登録された側から片側ずつ開く。車椅子用操作盤の行先ボタンは、最後に開いた扉の反対側を開く。あとから開く側の応答灯は、その扉を開くまで点けたままにする。
  - 戸の開閉制御は1組のまま。扉が開いているあいだに反対側で呼ばれたら（乗場の呼び・行先ボタン・開ボタン）、今の扉が閉まりきってから、発車せずに反対側の扉を開く。反対側の扉を開くときも到着チャイムを鳴らし、ランタンの点滅をやり直す。
  - ホールランタンは、開く（開いている）側の乗場だけ点ける。
  - 頂部の制御盤は、小さい機種では左の壁に収まらない（奥の乗場の戸が奥を占めるため）ので、重りの列の、乗場の壁の裏（設置用ブロックの真後ろ）の頂部に、昇降路の中を向けて付ける。
- かごの奥や横に出入口があるので、釣合い重りは横落とし（展望仕様と同じく、かごの右の列）にする。昇降路は1ブロック広くなる。
- 各階でどちらの扉を使うか（前／後または横／両方）は、設置用ブロックの設定画面の停止階の欄で階ごとに選ぶ。階床登録ツールの使い方は変えない。呼びは乗場もかごも側ごとに分け、押した側の扉だけ開く。
- かごの操作盤は、それぞれの出入口の袖壁に置く。左右の位置は、それぞれ今の「操作盤の左右」の設定に従う。
- 直角（L字）は、かごの奥行きが横の出入口の幅と両脇の袖壁（3pxずつ）より広い機種だけで選べる（P-6は奥行き20pxなので選べない）。
- 展望仕様（奥壁がガラス）とは、前後（スルー型）は組み合わせられない。直角（L字）とは組み合わせられる。

**扉の実装**（`core`の`DoorController`／`DoorGeometry`）

- 開閉時間と開放待機時間は実機並みとする（寸法と速度がどちらも1.5倍なので、時間は実機と同じ）。開くのに2.0秒、閉じるのに2.5秒。開放待機は乗場呼びで4秒、かご呼びで2秒。
- 開き具合は0（全閉）〜1（全開）で表し、動き始めと止まる直前をゆっくりにする。反転したときは、その時点の開き具合から残りの分だけの時間で開き直す。
- 戸の厚みは1px。かごの戸は袖壁のすぐ外側、乗場の戸はさらに敷居のすき間（1px）を空けた外側に置く。開くと、戸は出入口の両脇へ滑り込む。
- かごは戸が全閉になるまで発車せず、着床すると戸を開く。
- 乗場の扉はエンティティとし、開き具合は持たない。かごがその階に着床しているときだけ、かごの戸と同じ開き具合で動く。三方枠など動かない部分は、フェーズ2でブロックにする。
- セーフティシューは、閉動作中の戸板（かご・乗場とも）に生き物（LivingEntity）が触れたら反転する。アイテムなどでは反転しない。
- 多光軸ビームセンサーの検知領域は、かごの戸（いちばん外側のレール）と乗場の戸の間の敷居のすき間（1px）に、出入口の幅と全高で置く（`DoorGeometry#beamZone`）。閉動作中にここへ生き物が入っていたら、戸が触れる前でも反転する。セーフティシューと同じく、開いている側の出入口だけを見て、アイテムなどでは反転しない。
- 開ききっているあいだにビームが人を検知していたら、開放待機の時間を数え直し続ける（`DoorController#hold`）。戸閉アナウンスは流さず、流して閉め始めるのを待っていたら、それも取りやめる。検知がなくなってから開放待機の時間（と、自動で閉めるときの戸閉アナウンスの時間）がたつと閉め始める。これは反転ではないので、強制戸閉の反転の回数には数えない（開放が長く続いたときの強制戸閉は、別に数える）。
- 開ボタンは、使用キーを押したままのあいだ繰り返し押され、戸を開けたままにする。離してから開放待機の時間がたつと閉め始める。ほかのボタンは、押したままにしても繰り返さない。
- 扉の方式は、設置用ブロックの設定画面で機種の次に選ぶ（機種で選べない方式は出さない）。設置したあとは変えられない。
- 実装：機種と扉の方式を `core` の `CarSpec`（扉の方式は `DoorType`）にまとめ、出入口の幅と位置、戸の枚数と動き、操作盤を置く袖壁はここから求める。かごと乗場の扉のエンティティは、機種と扉の方式を同期データの1バイト（下位4ビットが機種、上位が扉の方式）で持つ。
- CO・4COの戸は袖壁より広いので、開くと少しかごの横へ出る（実機でも同じ）。2Sは戸袋の側の袖壁を戸1枚分にしてあるので出ない。

**2枚片開き（2S）**

- 全機種で選べる。出入口の幅はCOと同じ。
- 開く向き（戸袋の側）は、乗場から見て左開き・右開きを設置の設定で選ぶ。
- 2枚の戸は、開くと戸袋の側の袖壁の前に重なって入る。閉じたときの2枚の重なりは2pxとし、戸1枚の幅は（出入口の幅＋2px）÷2。
- かごの幅は変えず、出入口を戸袋と反対側へ寄せる。戸袋の側の袖壁は戸1枚の幅にし、残りを反対側の袖壁にする。

| 機種 | かご内の幅 | 出入口 | 戸袋の側の袖壁 | 反対側の袖壁 | 出入口のずれ |
| --- | --- | --- | --- | --- | --- |
| P-6・P-9・P-11 | 34px | 20px | 11px | 3px | 中央から4px |
| P-13・P-15 | 38px | 22px | 12px | 4px | 中央から4px |
| P-17・P-20 | 44px | 24px | 13px | 7px | 中央から3px |
| P-24・P-27・P-30 | 48px | 26px | 14px | 8px | 中央から3px |

- 戸はかご・乗場とも2本のレール（前後に並ぶ）に分かれるので、戸のある部分の奥行きがCOより片側1pxずつ増える。外側の戸は内側の戸の倍の速さで動く（開閉時間はCOと同じ）。
- かごの操作盤は、戸袋の側の袖壁に1つだけ置く（2Sでは操作盤の「左右」の設定を使わない）。反対側の袖壁は狭いので置かない。
- 乗場の三方枠は今と同じ幅（3または4ブロック）で、出入口の穴だけがずれる。乗場のボタン・表示器・ランタンは、今と同じく右の脇の中央に置く（脇の幅が左右で変わる）。

**4枚中央開き（4CO）**

- P-24・P-27・P-30で選べ、出入口をCOより広い実機どおりの1400mm（34px）にする（東芝エレベータの寸法表の4枚戸中央開きの値。P-17・P-20には4枚戸がない）。
- 戸は左右に2枚ずつで、開くと左右の袖壁の前にそれぞれ2枚が重なって入る。閉じたときの戸の重なりは1pxで、戸1枚の幅は（出入口の幅の半分＋1px）÷2＝9px。
- 袖壁は左右7pxずつで戸より狭いので、開いた戸はCOと同じく少しかごの横へ出る（実機でも同じ）。

- 戸はかご・乗場とも、左右それぞれ2本のレールに分かれる（2Sと同じく、戸のある部分の奥行きが片側1pxずつ増える）。外側の戸は内側の戸の倍の速さで動く。

## 音声とアナウンス

アナウンスはテンプレートで管理し、再生はクライアントごとに差し替え可能なProviderに任せる。

- **サーバーが送るもの**：アナウンスの種別（「到着」「上へ参ります」など）と階名だけ。
- **同梱音声Provider（標準）**：数字やチャイムなどの音声をOGGで同梱し、つなぎ合わせて再生する。
- **VOICEVOX Provider**（フェーズ5-1）
  - ローカルで動いているVOICEVOXエンジンのHTTP API（audio_query → synthesis）でWAVを生成し、キャッシュする。
  - 自由な階名（例：「ブランチマイニング場です」）をその場で読み上げられる。
  - WAVはSoundInstanceで独自のAudioStreamを返し、PCMのまま再生する。
  - エンジンが起動していないクライアントでは、同梱音声に自動でフォールバックする。
- **規約**：VOICEVOXはキャラクターごとに利用規約が異なり、クレジット表記が必要。同梱音声と設定画面にクレジットを表示する。
- メーカーの音声やロゴは使わない。

**アナウンスの実装**（`core`の`AnnouncementScript`）

- 文面：到着は「◯階です。」、行先方向は「上へ参ります。」「下へ参ります。」（方向が決まっていなければ流さない）、戸閉は「ドアが閉まります。」。階名は数字の階、地下（B1→地下1階）、屋上（R）に対応する。
- 到着して戸を開き始めるときに「◯階です。」を流し、戸が開ききったときに行先方向を流す。戸はアナウンスを待たずに開く。かごがいる階の乗場呼びに応えるときは、階の案内はせず行先方向だけを流す（戸がもう開いていればすぐに）。流すかどうかは設定で選べ、階の案内と行先方向の両方に効く。
- 戸が開ききっている間に、呼びの登録などで進行方向が決まったり変わったりしたら、その場で行先方向を流す。その停止で最後に流した方向と同じなら繰り返さない。戸閉アナウンスを流して閉め始めるのを待っている間は、戸閉アナウンスを途中で切らないよう流さない。
- 行先方向を流している間（流し始めてから1.2秒）に戸を閉めるときは、実機と同じく戸閉アナウンスを流さない。自動で閉めるときも、流さないので待たずに閉め始める。
- 戸閉アナウンスは、開放待機が終わって自動で閉めるときに流し、流し終わるまで（1.5秒）待ってから閉め始める。閉ボタンのときは流しながら待たずに閉める。設定で切ると、待ちもなくなる。待ち時間はクライアントの音声の長さに合わせられないので、サーバー側の固定値とする。
- アナウンスはかごの中（床から2.5ブロック）から鳴らす。乗場では鳴らさない。
- 基本方針：同じかごで別のアナウンスが流れているあいだは、新しいアナウンスは流さずに捨てる（流れているものを途中で切ったり、流し直したりしない）。クライアントの再生側で、鳴っている音声と、つなげて鳴らす続きが残っているかで判断する。サーバーも、自動で閉めるときの戸閉アナウンスを流しているあいだ（閉め始めるのを待っているあいだ）に閉ボタンが押されたら、戸閉アナウンスを送り直さない。
- 同梱音声は VOICEVOX（冥鳴ひまり、ノーマル）で生成する（`tools/sounds/make_announcements.py`）。階は読みが崩れないよう「◯階です。」までを1つのクリップにし、1〜50階、地下1〜5階、屋上を用意する。範囲外の階名では、階のクリップを省いて方向だけを流す。
- クレジット「VOICEVOX:冥鳴ひまり」は、MODの情報（mods.toml）に表示する。設定画面ができたら、そこにも表示する。

**VOICEVOX連携の実装**（フェーズ5-1）

- 設定はクライアントのコンフィグ（`config/realelevator-client.toml` の `[voicevox]`：`enabled`（既定はオフ）、`engineUrl`（既定 `http://127.0.0.1:50021`）、`speaker`（スタイルの番号、既定は冥鳴ひまり（ノーマル）の14）、`speakerName`（クレジット用の名前））。プレイヤーごとの設定。
- 設定画面：モッド一覧の「設定」から開く。使うかどうか、エンジンの URL、話者（「話者を読み込む」でエンジンの `/speakers` から一覧を取り、キャラクター名（スタイル名）で選ぶ）、「試しに読む」（「1階です。」を自分の位置で鳴らす）。選んだ話者のクレジット「VOICEVOX:キャラクター名」と、キャラクターごとの利用規約に従う旨を出す。
- オンなら、到着・行先方向・戸閉のすべてのアナウンスを、選んだ話者で読み上げる（文は `AnnouncementScript#text`）。エンジンの `audio_query` → `synthesis` で WAV を作り、PCM のまま鳴らす（ストリーミングのサウンドイベント `announce.voicevox` に、ファイルの代わりに PCM を流す）。かごの中（床から2.5ブロック）から鳴らす。同じかごで別のアナウンスが鳴っている、または作っているあいだに届いたものは捨てる。
- 作った WAV は、話者と文ごとにメモリと `realelevator/voicevox_cache/<話者>/<文のSHA-1>.wav` に覚え、同じ文は作り直さない。初めての文は作るのに時間がかかるので、読み込まれているかごの停止階の到着の文と、行先方向・戸閉の文を、5秒おきに前もって作っておく。
- エンジンにつながらなかったら、そのアナウンスは同梱音声で鳴らし、30秒はエンジンに問い合わせずに同梱音声を使う。作るのが1.5秒より遅れたアナウンスも、間が抜けるので同梱音声で鳴らす。
- 読み上げ名：停止階ごとに「読み上げ名」（32文字まで）を設定画面の停止階の欄で入れられる。あれば到着の案内を「（読み上げ名）です。」にする（「ブランチマイニング場です。」など）。同梱音声では読めないので、読み上げ名のある階では、同梱音声は階の案内を省いて方向だけを流す。サーバーは到着のアナウンスに読み上げ名を付けて送る。

## 設置方法と動力

設置はウィザード式、方式は機械室レスとし、高速仕様もネザースターを動力にして機械室レスで動かす。

**設置の流れ**

1. 最下階の乗場に設置用ブロックを置く。
2. 階床登録ツールで、各階に立ってクリックし、停止階を登録する。二方向出入口の場合は、各階でどちら側の扉を開くかを設定画面の停止階の欄で選ぶ。
3. 設置用ブロックのGUIで以下を選ぶ。
   - 機種（P-6／P-9／P-11／P-13／P-15／P-17／P-20／P-24／P-27／P-30）
   - 扉の方式（中央開き／2枚片開き／4枚中央開き）と、二方向出入口（なし／前後／直角）
   - 速度の仕様
   - 階名（アナウンスでも使う）
   - デザイン（プリセット＋部位ごとの変更）
4. 昇降路をホログラムでプレビューし、邪魔なブロックがある箇所を赤く表示する。
5. 確定すると、ガイドレール、各階の乗場ドア、三方枠、乗場ボタン、階床表示器を一括で設置する。

設置後も、レンチで「リニューアル」としてデザインを変更できるようにする。

**設置後の制御盤とレンチ**

- 今の「制御盤ブロック」は**設置用ブロック**とする。設置すると設置用ブロックは消え（その場所は空く）、設定とネザースターは昇降路の頂部の**制御盤**に移る。実機の機械室レスで、制御盤が巻上機の近くにあるイメージ。乗場の壁に置いた設置用ブロックから巻上機まで遠くなりすぎる問題もなくなる。
- 頂部の制御盤は縦2ブロックのブロック（扉のような上下2つのブロック）で、下のブロックのブロックエンティティが計画（`ElevatorPlan`：設置用ブロックの場所と向き、停止階、階名、設定）・ネザースター・かごとの紐付けを保存する。形は壁に付いた幅12px・厚み4pxの箱（仮、鉄の扉のテクスチャ。横落としでかごの横のすき間（4px〜）に収まる厚み）。かごは制御盤の場所を覚えている。
- 置く場所は天井から下2ブロックで、後ろ落としでは昇降路の左奥の隅（奥の壁の中央）、横落としでは左の壁の奥寄り（`ShaftLayout#controllerCells`／`controllerBoxes`）。どちらも、かご・釣合い重り・巻上機・ロープ・ガイドレールと重ならない。
- 頂部の制御盤は、サバイバルでは壊せない。撤去はレンチの「解体」だけで行う。クリエイティブやコマンドで消されたときは、エレベーターごと解体し、設置用ブロックとネザースターは最下階の乗場（設置用ブロックを置いていた場所）に落とす。
- **レンチ**：どの階でも、乗場の操作盤のあたり（三方枠）をレンチで右クリックするとメニューが開く。素手の右クリックは、今までどおり乗場のボタンを押す。
  - レンチは `c:tools/wrench` タグのアイテムならどれでもよく、ほかのMODのレンチでも開ける。このMODの「保守用レンチ」（`maintenance_wrench`）もこのタグに入れる。
  - メニューでは、設置したあとに変えられる設定（階名・配置・アナウンス、デザインのリニューアル）を変える。
  - メニューの「解体」は確認画面を出し、「はい」で、かご・乗場の扉・ガイドレール・頂部の制御盤を撤去する。設置用ブロックとネザースターはプレイヤーの持ち物に戻る（入らなければ足元に落とす）。
  - メニューの画面は、設置用ブロックの設定画面と同じ並べ方で、配置・アナウンス・階名の設定と停止階の欄、下に「解体」「完了」を置く。
- **管理の権限**：設置したプレイヤーを設置者として頂部の制御盤が覚える（`ElevatorAccess`）。設置者、許可されたプレイヤー、OP（権限レベル2以上）だけが次の操作をできる。
  - リニューアルと設定の変更（メニューを開くことを含む）、解体、群に入れる・外す、運転切替盤につなぐ・外す（レンチでエレベーターを選ぶことを含む）、仕様書の反映。仕様書の写し取りと、乗場やかごのボタンは誰でもできる。
  - 許可するプレイヤーは、メニューの「権限…」で、オンラインのプレイヤーの名前を指定して追加、削除する（16人まで）。変えられるのは設置者とOPだけ。
  - 設置者の記録がないエレベーター（この機能より前に設置したもの）は、最初に上の操作をしたプレイヤーを設置者にする。

**設置の実装**（`core`の`ShaftLayout`）

- 設置用ブロックは乗場の壁の列に置き、正面（置いたプレイヤーの方）が乗場側になる。出入口は乗場から見て設置用ブロックの2ブロック左が中心で、かごはその奥。設置用ブロックの高さが最下階になる。
- 乗場の壁の列は1ブロックの厚みで、乗場の戸はその列の昇降路側の面に付く。三方枠の範囲は、出入口を残して壁の列の幅3ブロック・高さ4ブロックを埋める（当たり判定はこの範囲）。その中に、枠と、枠のまわりの壁（カメレオン）を描く。乗場のボタン・表示器・ランタンは乗場側の面に付ける。三方枠は1px単位の形なので、乗場の扉のエンティティが当たり判定と描画を持つ。
- 昇降路は幅3ブロックで、奥行きはかごの奥行きに釣合い重りの1列を足した分。高さは最下階のピットから最上階の頂部すき間まで（リアル寸法：ピット2・頂部6、省スペース：ピット1・頂部4）。
- 階床登録ツールは、設置用ブロックを右クリックしてつなぎ、停止階にしたい階の床に立って右クリックすると登録、もう一度で解除する。設置用ブロックから水平に16ブロック以内で使える。停止階の間隔は4ブロック以上。
- 設置用ブロックの設定画面で、機種・速度・ピット・配置・アナウンス・階名（4文字まで）を選び、プレビュー（昇降路の範囲、各階のかご、邪魔なブロックを赤で表示）を確かめてから設置する。邪魔なブロックがあると設置できない（草や水など置き換えられるものは取り除く）。
- 設置すると、ガイドレール（仮、かごの左右の細い柱）と頂部の制御盤を置き、かごと各階の乗場の扉を出し、設置用ブロックを消す。設置したあとは、レンチのメニューで階名・配置・アナウンスだけ変えられる（機種・速度・加速度・ジャーク・ピットは変えられない）。
- 設置する前の設置用ブロックを壊すと、はめていたネザースターを落とす。
- 高速仕様はネザースターで解放するまで、設定画面では普通（低）・普通（高）だけを選べる。
- 設定画面はコンテナ式で、下のボタンで「設定」と「動力」の表示を切り替える。「動力」の表示に、ネザースターのスロットと持ち物を出す。加速度とジャークのスライダーは「設定」の表示にあり、高速仕様のときだけ動かせる。
- 高速仕様で設置しているあいだは、ネザースターを取り出せない。設置する前に取り出すと、高速仕様の設定は普通（高）に戻る。

**設置の材料**

- 設置用ブロックのレシピに、かごと頂部の制御盤の分を含める。設置するときは、さらにガイドレールと乗場の扉の分を、「設置する」を押したプレイヤーの持ち物から使う（`InstallMaterials`）。
  - ガイドレール：2ブロックごとに鉄インゴット1（端数は切り上げ）
  - 乗場の扉（三方枠・ボタン・表示器を含む）：1つごとに鉄インゴット4とレッドストーン1（二方向出入口の階は2つ）
- 足りなければ設置しない。設定画面の状態の欄に、使う材料と、足りないかどうかを出す。クリエイティブでは使わない。
- 使った材料は頂部の制御盤が覚えておき、解体すると、設置用ブロック・ネザースターと一緒にすべて返す。

**レシピ**（バニラの材料だけ。材料を持つとレシピ本に出る。`tools/data/make_recipes.py` で書き出す）

| アイテム | レシピ |
|---|---|
| 設置用ブロック | 鉄ブロック1（中央）、鉄インゴット4（四隅）、ピストン2（左右）、レッドストーン2（上下） |
| 階床登録ツール | レッドストーン・鉄インゴット・棒を斜めに |
| 保守用レンチ | 鉄インゴット4（スパナの形） |
| 運転切替盤 | 石3（上）、鉄インゴット2とレバー1（中）、レッドストーン1（下） |

**プロファイルと仕様書**

同じ建物でエレベーターの仕様と意匠をそろえたり、同じ設定を何度も作り直さずに済むように、設定をプロファイルとして保存して読み込めるようにする（`ElevatorProfile`）。

- **含めるもの**：設置する前だけ変えられる項目（機種、扉、速度と加速度・ジャーク、ピット、釣合い重りの位置、二方向出入口、展望仕様）と、設置したあとも変えられる項目（器具の配置、アナウンス、ランディングオープン、意匠（かごと乗場））。名前（32文字まで）を付けられる。
- **含めないもの**：停止階・階名・読み上げ名・停止階ごとの出入口。建物ごとに階床登録ツールと設定画面で決める。
- **反映のしかた**：設置用ブロックにはすべての項目を入れる（停止階・階名などはそのまま）。高速仕様は、ネザースターがはまっていなければ速度だけ変えずに、その旨を出す。設置したかごには、設置したあとも変えられる項目だけを入れる（機種・速度などは変わらない）。器具の配置は、その停止階で選べないもの（扉の上の表示器など）を直して入れる。
- **手元のファイル**：クライアントの `realelevator/profiles/<名前>.json` に1つずつ保存する（どのワールド・サーバーでも使える）。設置用ブロックの設定画面と保守用レンチのメニューの「プロファイル…」から画面を開き、一覧から選んで「読み込む」、今の設定に名前を付けて「保存」（同じ名前は確認して上書き）、「削除」（確認する）ができる。
- **仕様書**（`specification`）：プロファイルを書いておくアイテム。マルチプレイで人に渡せる。
  - しゃがんで設置用ブロックか乗場の操作盤のあたり（三方枠）を右クリックすると、その設定を写し取る（名前はなくなる）。
  - そのまま右クリックすると、書いてある内容を反映する（上の反映のしかたのとおり）。
  - 何もないところで右クリックすると、プロファイルの画面を開く。一覧から選んで「仕様書に書く」、仕様書の内容に名前を付けて手元に保存できる。
  - 白紙の仕様書は反映も保存もできない。ツールチップに名前と、機種・扉・速度を出す。

**動力**

- **普通仕様**：動力の条件はない（いつでも動く）。
- **高速仕様**：設置用ブロック（設置後は頂部の制御盤）のスロットにネザースターを1個はめると解放される。ビーコンと同じく、ネザースターは消費しない。
- **運転と休止**（普通仕様・高速仕様とも）：マイクラのレッドストーン信号はレッドストーンブロックやトーチから尽きずに得られ、「停電」が起こりえないので、信号は受電ではなく運転の切り替えに使う。
  - **運転切替盤**（`PowerReceiverBlock`）：どこにでも置ける。まわりからレッドストーン信号を受けているあいだ、つないだエレベーターは通常運転し、正面のランプが緑に点く。信号がないあいだは休止する（ランプは暗い赤）。
  - つなぎ方：保守用レンチ（`c:tools/wrench` のレンチならどれでも）を持ってしゃがみながら乗場の操作盤のあたりを右クリックしてエレベーターを選び（レンチに覚える）、そのレンチで運転切替盤を右クリックする。1つの運転切替盤には1台だけつなぐ。しゃがみながらレンチで運転切替盤を右クリックすると外れる。しゃがまずにレンチで右クリックすると、つないでいるか・通常運転か休止かを表示する。
  - 運転切替盤をつないでいないエレベーター（それまでに設置したものを含む）は、常に通常運転。運転切替盤を壊すと、つなぎが外れて通常運転に戻る。運転切替盤のあるチャンクが読み込まれていないあいだは、最後の状態のまま。
  - **休止に切り替えたとき**（以前の停電時自動着床の動作）：呼びをすべて消す。走行中なら減速が間に合う最寄りの階（なければ行先）に止まり、止まっていればその階で、戸を開けて10秒（乗客が降りる時間）待ってから閉め、休止する。
  - **休止中**：乗場ボタンも行先ボタンも受け付けない。階床表示器はハイフン（「--」）を出し、ホールランタンと応答灯は消え、アナウンスと到着チャイムも鳴らさない。開ボタン・閉ボタンは効く。信号が戻ると通常運転に戻る（消えた呼びは押し直す）。

## デザインシステム

マイクラのドット調を維持しながら日本式エレベーターを表現し、デザインは「部位 × 素材」のデータ駆動で管理する。

**目指す意匠**（フェーズ4の具体化。未実装）

参考は、現行の国内メーカーの標準型（ステンレスとブロンズ、木目の内装）。実在メーカーのロゴ・社名・表示内容は再現せず、部品の並びと雰囲気だけを借りて、ドット絵に落とし込む。

- **かごの正面**：扉はブロンズ調ステンレス（オリジナルのドット絵）、袖壁とトランサムは明るいステンレスのヘアライン、側壁は木目（バニラの板材を参照）。
- **主操作盤**：袖壁に、床から天井近くまでの縦長のステンレス板を1px浮かせて貼る。上から、黒い表示窓（矢印と階）、黒い帯、非常呼びボタン、行先ボタン（2列）、開・閉ボタン、開延長ボタン（設定で付ける。開ボタンの下）の順。
- **車椅子用操作盤**：ステンレスのヘアラインの横長の板（後ろのプレート。主操作盤・乗場の操作盤と同じ素材）をきちんと描き、上部の黒い帯の中央に表示器、端に青い車椅子マークを置く。行先ボタンは2段で、下の段が若い階（例：1〜6、その上に7〜12）。最下段は、左に非常呼び、右に開・閉。今までどおり両側の側壁に付ける。
- **ボタン**：今までどおり四角のボタンにする（応答灯の点は付けず、図柄が光る）。ボタンを少し大きく（3px角など）し、面に行先ボタンは階、開・閉ボタンは開・閉のマーク（◀▶・▶◀）を描く。面の図柄だけは1pxを4分割した細かいドットで描く（1ブロック＝16pxの原則の例外。未決事項の「ボタンの階数表示」はこれで決める）。
- **表示器**：標準の色は今のアンバーのまま、ほかの色も選べるようにする。主操作盤の表示窓は大きい字（5×7ドット）にする。
- **部品の見た目の実装**（フェーズ4-1。`core`の`CarPanelLayout`／`WheelchairPanelLayout`／`ButtonGlyphs`／`LargeDotFont`）
  - 主操作盤：袖壁の幅いっぱいの板（床から2px〜天井の2px下、厚み1px）。上から、表示窓（高さ8px。幅はどの機種も、袖壁がいちばん狭い機種で両端に0.5pxずつ板が残る幅（6px）にそろえ、袖壁の中央に置く）、黒い帯（1px）、非常呼びボタン（左の列）、行先ボタン（2列）、開・閉ボタン、開延長ボタン（設定で付ける。開ボタンの1段下）。ボタンは板の面から0.5px出っ張る。袖壁が狭く、3px角を2列に並べると両脇に1pxずつの余白が残らない（9px未満の）機種では、はじめから2px角にする。開・閉ボタンの下端は22pxで、収まらなければ12pxまで下げ、それでも収まらなければ2px角のボタンに、さらに収まらなければ非常呼びを省く（3px角で10階床、2px角で16階床、非常呼びを省いて18階床まで収まる）。
  - 表示窓：0.5px のドットで、上に矢印（5×5）、下に 5×7 ドットの階名（`LargeDotFont`。3文字の階名は 3×5 ドット）。表示器を扉の上にする設定や、左の操作盤に表示器を付けない設定では、表示窓を付けない。
  - 車椅子用操作盤：板（側壁から1px）の上部の黒い帯（高さ5px）に、表示窓（9×4px、0.5px のドットで矢印と階名を横に並べる）と、見る人から見て右端の青い車椅子マーク（4px角、白い図柄は1/4px のドット）。行先ボタンは下の段から若い階を左から右へ並べ、列は奥行きに収まるだけ（段は2段から）。いちばん下の段は左に非常呼び、右に開・閉。板の上端が52pxを超えるときは2px角のボタンにする。
  - ボタンの図柄：1/4px のドットで、行先ボタンは階名（3×5 ドット、ドットにある文字を3文字まで。フォントで描く設定ではフォントで縮めて全部）、開・閉は ◀|▶・▶|◀、開延長は ◀|▶ と「＋」、乗場のボタンは矢印、非常呼びは「SOS」。図柄の下の応答灯の点は付けず、応答灯がつくと図柄そのものが表示器の色で光る。乗場の車椅子用ボタンも、普通のボタンと同じ色。
  - 表示器の色：設定画面の「表示器の色」で、アンバー（既定）／白／青から選ぶ。階床表示器・ホールランタン・ボタンの応答灯に効く。
  - ボタンの押せる範囲：視線がブロックや、かごの壁・床・天井・戸、乗場の戸にさえぎられていれば押せない（戸の窓越しに見えるボタンも押せない）。
  - ボタンのクリック音：押したときと離したときに鳴らす。開ボタンを押したままのあいだの繰り返しでは鳴らさない。
  - 非常呼びボタン：飾りで、押すと短い音（`tools/sounds/make_beep.py` で合成）が鳴るだけ。
  - 乗場のボタンも3px角にした（▲と▼のすき間2px。並びはフェーズ4-3で操作盤の板に合わせて決め直した）。
- **かご内装の実装**（フェーズ4-2。`core`の`InteriorConfig`／`InteriorGeometry`）
  - 素材を選ぶ部位は、壁（側壁と奥壁）、前壁（袖壁とトランサム）、ドア（かごと乗場の戸）、床、幅木。素材はブロックのIDで持ち、そのブロックのモデルの側面のテクスチャを使う（リソースパックに追従する）。候補はブロックタグ `realelevator:materials/wall`（壁・前壁・ドア・幅木）と `realelevator:materials/floor`（床）で、データパックから足せる。タグにない素材を指定されたら初期値に戻す。
  - オリジナル素材は、建築にも使えるブロックとして登録する（クリエイティブの「建築用ブロック」）：木目パネル（明るい・中間・濃い）、ステンレス（ヘアライン・鏡面・エッチング）、ブロンズ調ステンレス、黒ステンレス（ヘアライン）、石目調ビニル床（灰・ベージュ）。テクスチャは `tools/textures/make_materials.py` で描く16pxのドット絵。レシピは「レシピ」の表のとおり。
  - 黒ステンレス（ヘアライン）は、黒コンクリートより少し明るい黒に、ステンレスと同じ細い縦筋を入れたもの。黒コンクリートは暗すぎるので壁の素材の候補から外し、これに入れ替えた（黒コンクリートを選んでいたかごは、リニューアルで設定を反映するときに黒ステンレスに置き換える）。
  - 初期値は標準のプリセットと同じ（壁：木目（中間）、前壁：ステンレス（ヘアライン）、ドア：ブロンズ調、床：石目調ビニル（灰）、幅木：ステンレス（ヘアライン）、天井：ダウンライト、手すり：両側の側壁）。
  - 素材は、設定画面の「デザイン…」から開くデザインの画面で選ぶ（フェーズ4-5）。
  - 壁の継ぎ目：側壁・奥壁を幅1.5ブロック以下なら2枚、それより広ければ3枚に分ける、1/4pxの暗い縦の線。幅木の上から天井まで。
  - 幅木：側壁と奥壁の下端の高さ2pxの帯。壁の面にわずかに浮かせて重ね、出っ張らせない。
  - 天井：ダウンライトは、明るい灰色の板に2px角の照明を4つ（幅と奥行きの1/4と3/4の位置）。間接照明風は、まわり3pxの縁取りを1px下げ、中央を光る板にする（かごの表示器を扉の上に付けるときは、トランサムの表示器を隠さないよう、縁取りの前の辺を下げない）。全面照明は、天井全体を光る板にする。ダウンライトと間接照明風は、奥行きを3つに分ける継ぎ目の線を描く（全面照明は継ぎ目が見えないので描かない）。
  - かご内の明るさ：かごの床・壁・天井・戸・操作盤などの、かごの中を向く面は、ブロックの明るさ15で描く（空の明るさはまわりのまま）。外を向く面はまわりの明るさ（4-6）。天井の光る部分は、まわりにかかわらず最も明るく描く。
  - 手すり：高さ13〜14pxに1px角の暗い棒を、壁から1px離して金具3つで支える。壁の両端から3pxずつ空ける。
- **乗場の実装**（フェーズ4-3。`core`の`LandingLayout`）
  - 設定画面に、乗場の枠（細枠／幕板付き）、乗場の操作盤（壁付け／埋め込み）、乗場の枠の素材（既定はブロンズ調）、乗場の壁（「まわりに合わせる」（既定）か壁の素材の候補）、ランタンの背面プレート（既定はあり）、群管理向け（既定はオフ）を置く。乗場の設定はかご内装の設定（`InteriorConfig`）といっしょに持つ。
  - 枠：出入口のまわりに幅4px、壁の面から1px出っ張る枠。見込み（厚み）は乗場の戸の前から。幕板付きでは、上の部分を三方枠の範囲の上端（4ブロック）まで伸ばす。埋め込みの操作盤では、右の枠を7pxにする。
  - 壁付けの操作盤：枠のすぐ右に1px空けて、幅5px・厚み1pxのステンレスの板を貼る（片開きのP-13・P-15など脇が9pxしかないときは、枠に接して貼る）。上から、表示窓（4×7px）、▲▼、車椅子マーク（4px）、車椅子用の▲▼、鍵スイッチ（2px角、飾り）。▲と▼などのすき間は2px。▼の下端は、表示窓があれば29px、なければ（群管理向けか、表示器が扉の上）25px。埋め込みでは、同じ並びを右の枠に埋め込む（板はない）。
  - 乗場の表示窓の表示器：0.5px のドットで、上に矢印、下に 3×5 ドットの階名。
  - ホールランタンの背面プレート：ランプのまわり2pxのステンレスの板（厚み1px）で、ランプはその上に付く。壁に付けるときだけで、幕板や埋め込みの枠に付けるときは付けない。脇が狭いときは、三方枠の範囲と枠からはみ出さないよう削る。
  - 群管理向け：オンにすると乗場の階床表示器を付けず、ランタンの位置で「扉の右」を選べる。オフでは「扉の右」は選べない（選ばれていれば扉の横へ移す）。
  - 枠のまわりの壁（カメレオン）：三方枠の範囲のうち枠の外を、ブロックの格子に合わせて1ブロックずつに分け、乗場の側の面だけを、まわりのブロックとテクスチャの継ぎ目がそろうように描く。「まわりに合わせる」では、三方枠の範囲のすぐ左右と上の、同じ壁の列の不透明な立方体のブロックのうちいちばん多いものの、乗場を向いた面のテクスチャ（草などは色も）を使う。クライアントが1秒おきに調べ直す。まわりにブロックがなければ滑らかな石。
  - 敷居：かごと乗場の出入口の幅で、床と同じ高さのアルミ色の薄い板に、戸のレールごとの溝の線を引く。かごは袖壁の内側の面からかごの戸の外側まで、乗場は乗場の戸から枠の前の面まで（多光軸ビームのすき間は空ける）。
  - 乗場の明るさ：乗場の扉のエンティティの位置は昇降路の中なので、乗場の器具は出入口の前のブロックの明るさで描く。
  - 枠のまわりの壁は、昇降路の側（裏）の面も描く（4-6で直した。最初は乗場の側だけで、裏から見ると抜けて見えた）。
- **防犯窓と展望仕様の実装**（フェーズ4-4。`core`の`DoorWindows`、`CarGeometry`の`GLASS`、`InteriorGeometry`の`MULLION`）
  - 防犯窓：設定画面の「防犯窓」で、なし（既定）／標準／大型／超大型を選ぶ（リニューアルでも変えられる）。扉の方式によらず、かごと乗場のすべての戸板に付ける。窓は戸板の幅の中央で、上端は戸の上端から8px。幅は戸板の幅に割合（標準1/3、大型・超大型2/3）を掛け、左右の枠が同じ幅になるよう戸板の幅と偶奇をそろえた整数 [px] にする（P-11の中央開きで標準4px・大型6px）。高さは戸の高さ50pxの1/3・3/5・4/5で、17・30・40px。戸板は窓のまわりの4つの箱に分けて描き、穴に網入りガラスをはめる（当たり判定は戸板のまま）。
  - ガラスのテクスチャ：網入りガラス（`wired_glass`。うっすら青みのある半透明の地に、4pxおきの斜めの網）と展望のガラス（`clear_glass`。ほぼ透明の地に、斜めの映り込みの筋）。`tools/textures/make_glass.py` で描き、ブロックのアトラスに足す（`assets/minecraft/atlases/blocks.json`）。半透明の描画（`entityTranslucent`）で、ほかを描き終えてから描く。
  - 展望仕様：設置用ブロックの設定画面の「展望仕様」でオン／オフ（既定はオフ、設置前だけ）。オンにすると釣合い重りは横落としに決まり、二方向出入口（前後）はオフになる（逆も同じ）。奥壁を高さ15pxの腰壁と、その上から天井までのガラスに分ける（ガラスも当たり判定を持つ）。ガラスは、壁の継ぎ目と同じ位置の縦のステンレスの枠（1px）で2〜3枚に分け、奥壁の継ぎ目は腰壁の分だけ描く。手すりの設定がなし以外なら、両側の側壁だけの設定でも奥壁（ガラスの前）にも付ける。
- **プリセットと設定画面の実装**（フェーズ4-5）
  - **プレビュー**：設置用ブロックの設定画面と保守用レンチのリニューアル画面では、右の停止階の欄の上の「停止階／かご内／乗場」で、停止階の欄をプレビューに切り替える。デザインの画面では、素材の候補の下に、「かご内／乗場」を切り替えて出す。今の設定（機種・扉・二方向出入口・展望仕様、器具の配置、内装と乗場の意匠、階名、表示の文字）で、画面の中だけに作ったかごと乗場を描き、設定を変えるとすぐ反映する。かご内は奥の壁の前から扉の方を見て、乗場は正面から見る。ドラッグで左右に一周、上下に85°まで回せる（かご内は見回し・見上げ見下ろし、乗場は回り込み・見る高さを変える）。ホイールで拡大・縮小する（0.7〜4倍。視野を狭める・広げる）。視野は横の広さ（80°を拡大率で割ったもの）で決め、範囲の縦横比によらず横に見える広さをそろえる。設定画面のプレビューは、高さを幅の1.2倍までにする。デザインの画面では、素材の候補にどの部位の候補も収まる段数を先に取り（候補が多くてもプレビューに80pxは残す）、残りの高さをプレビューにして、幅は高さの1.8倍までにして中央に置く。表示器には見せる階の階名と上の矢印を出し、ホールランタンと乗場の▲を点ける。扉は閉めたまま。かごは、設置する前は今の設定で設置したときの位置（最下階）、リニューアルではメニューを開いた乗場の階に置く（乗場の壁の「まわりに合わせる」は、その位置のまわりのブロックで描く）。
  - デザインの画面：設置用ブロックの設定画面と保守用レンチのリニューアル画面の「デザイン…」から開く。左の列にプリセット（選んで「適用」）と、天井・手すり・防犯窓・乗場の枠・乗場の操作盤・ランタンの背面プレート。中の列に素材を選ぶ部位（壁、前壁、トランサム、ドア、床、カーペット、幅木、乗場の枠、乗場の壁）。右に、選んだ部位の候補のブロックをアイテムのアイコンで並べ、クリックで選ぶ（多ければホイールでスクロール、名前はツールチップ）。トランサムの「前壁と同じ／ドアと同じ」、乗場の壁の「まわりに合わせる」、カーペットの「なし」は、候補の上のボタンで選ぶ。値を変えるたびに設定を送る。
  - プリセット：データパックの `data/<名前空間>/elevator_presets/<名前>.json` で定義する（形式は `DesignPreset` の説明）。書かれていない項目は標準の値。同梱は標準・マンション・オフィス・高級・展望の5つ（上の表のとおり。オフィスはかごの表示器を扉の上（トランサム）に、高級は乗場の枠を滑らかなクォーツに、展望は展望仕様と手すり「側壁と奥壁」）。サーバーで読み込み、ログインしたときとデータパックを読み込み直したときにクライアントへ送る。プリセットを適用すると、かごと乗場の素材と設定（とかごの表示器の位置）がまとめて入る。展望仕様は設置する前ならオン／オフも入る（オンなら二方向出入口はオフ）。リニューアルでは展望仕様は変えられないので、その旨を画面に出す。
  - カーペット：なし（既定）／16色。床の縁を2px残して、厚み1pxの板を敷く（バニラのカーペットのテクスチャ）。バニラと同じく1pxの段として当たり判定を持つ。
  - トランサム：部位「トランサム」で、前壁と同じ（既定）・ドアと同じ・素材を選ぶ。
  - 自由設定：サーバーのコンフィグ（`serverconfig/realelevator-server.toml` の `freeMaterials`、既定はオフ）でオンにすると、デザインの画面に「手に持っているブロックを使う」が出て、手に持った不透明な立方体のブロック（ブロックエンティティを持たないもの）を、カーペット以外の部位の素材にできる。サーバーも同じ条件で確かめ、選べない素材は初期値に戻す。
- **乗場**：枠と操作盤を別々に選ぶ（組み合わせて4通り）。枠・扉は既定でブロンズ調（扉と同じ色）。
  - **枠**
    - **細枠**：出入口のまわりに細い枠（実機 約150mmの1.5倍で4px前後）を、壁から少し出っ張らせて付け、枠の厚み（見込み）も描く。
    - **幕板付き**：細枠の上の部分を、三方枠の範囲の上端（天井近く）まで伸ばして幕板にする。
  - **操作盤**
    - **壁付け**：枠のすぐ右（乗場から見て）の壁の面に、縦長のステンレス板を貼る。上部の黒い表示部に矢印と階、その下に▲▼、車椅子マーク、車椅子用の▲▼、いちばん下に鍵スイッチ（飾り）。
    - **埋め込み**：右の枠を幅広にして、上部に表示器、中ほどに▲▼と鍵スイッチ、下に車椅子マークと車椅子用の▲▼を埋め込む（左の枠は細いまま）。
  - **枠の外の壁（カメレオン仕様）**：扉の高さ（約3.1ブロック）と出入口の幅がブロックの格子にそろわないので、三方枠の範囲（幅3〜4ブロック×高さ4ブロック）はほぼすべてのマスに出入口か枠がかかり、プレイヤーがブロックを置ける場所は残らない。そこで三方枠の範囲のうち枠の外の部分は、乗場の壁としてエンティティが描く。既定では、三方枠の範囲のすぐ左右と上の、同じ壁の列のブロックのうちいちばん多いものの見た目をまね、壁を張り替えると追従する（まわりにブロックがなければ既定の素材）。設定で別の素材も選べる。
  - **敷居**：乗場とかごの戸の下に、アルミ色の薄い帯（床と同じ高さ、戸の溝の線付き）を描く。
  - **ホールランタン**：形は今の上下2段の棒状のまま。位置は、付けない／扉の横（細枠のすぐ左の壁に縦長）／扉の上（枠の上の壁、幕板付きなら幕板に横長）。ステンレスの背面プレートの有無を設定で選ぶ（既定はあり。なしなら壁にランプだけ）。
  - **群管理向け（表示器なし）**：乗場の階床表示器（現在の階と方向）を付けず、ホールランタンだけにする設定。複数台の群管理（フェーズ5）を想定したもの。このときは、扉の右側にも、左と同じ大きさのホールランタンを付けられる（扉の両横）。右側では、ランタンを上（扉の上端の高さあたり）に置き、その下に操作盤を置く。壁付けの操作盤は表示部のない短い板（▲▼、車椅子マーク、車椅子用の▲▼だけ）になる。埋め込みの操作盤では、右の枠の表示器の場所にランタンを置く。
- **天井**：次の3種類から選ぶ（あとで増やすかもしれない）。全面照明のほかは天井の板の継ぎ目（細い線）を描く。
  - **ダウンライト**：明るい灰色の平らな天井に、四角い照明を4つ（四隅寄り）。光る部分だけグロウストーン調にする。
  - **間接照明風**：天井のまわりを額縁のように一段下げて縁取り、中央の一段上がった部分を光る板にする。
  - **全面照明**：天井全体を光る白い板にする（継ぎ目は描かない）。
- **照明と明るさ**：かごはエンティティなので、照明で周りを実際に照らすことはできない。代わりに、かごの中（壁・床・天井・操作盤など）は、周りの明るさにかかわらず照明がついている明るさで描き、光る部分はさらに白く描く。中にいるプレイヤー自身は明るくならない。
- **手すり**：車椅子用操作盤のすぐ下の高さに、暗い色の四角い棒をステンレスの金具（3つ）で支える形。設定で、なし／両側の側壁（既定）／側壁と奥壁を選ぶ。二方向出入口の奥には付けない。展望仕様では、ガラスの奥壁の前にも付ける（腰壁の高さ）。
- **鏡**：付けない。マイクラには車椅子がなく、車椅子用操作盤は「マイクラの操作が苦手な人のために、開放時間が長くなる操作盤」という位置づけなので、車椅子で後ろ向きに降りるための鏡はいらない。
- **防犯窓**：かごと乗場の両開きの戸の、それぞれの戸板に縦長の窓を開ける。角は丸めない（四角）。ガラスは網入りガラスで、斜めの網をドットで描いた半透明のガラスにする。
  - **標準**：細め（戸板の幅の約1/3）で、戸の上から約1/6の位置から、戸の高さの約1/3の長さ。
  - **大型**：広め（戸板の幅の約2/3）で、戸の上から約1/6の位置から、戸の高さの約3/5の長さ。
  - **超大型**：大型と同じ幅で、縦をさらに長くする（戸の高さの約4/5）。

**アートの方針**

- 全部位で1ブロック＝16pxの解像度に統一する。高解像度のテクスチャやなめらかなグラデーションは使わない。
- 寸法は1/16ブロック単位に丸め、ドットの格子を揃える。
- かごの3Dモデルは寸法からプログラムで生成し、素材のテクスチャを敷き詰めて貼る。

**個別の機能**

- **トランサム**：素材を前壁と同じ（既定）／ドアと同じ／別にするかを選べる。かご内の階床表示器を埋め込むこともできる（かごの表示器の「扉の上」）。
- **防犯窓**：なし／標準／大型／超大型の4種類（下の「目指す意匠」を参照）。かごの扉と乗場の扉の窓位置が揃っていると、かごの中が見える。
- **車椅子用操作盤の位置づけ**：マイクラには車椅子がないので、マイクラの操作が苦手な人のために、開放時間が長くなる操作盤として置く（名前と車椅子マークは実機に合わせる）。
- **展望仕様**：かごの奥壁だけをガラスにする（側壁はガラスにしない）。奥壁は腰壁付きで、下の方（手すりの高さくらいまで）は壁、その上から天井までをガラスにする。昇降路の奥の壁（景色の側）は今までどおりプレイヤーが作る（ブロック・ガラス・開けたままのどれでもよく、MODは置かない）。ガラスは専用のレンダリングパスで描く。釣合い重りは横落とし（右側）にして、奥の景色にかからないようにする（「昇降路の機構と描画」を参照）。二方向出入口の前後（スルー型）とは組み合わせられない。
- **ボタン**：四角のボタンの面に図柄を描く（下の「部品の見た目」）。応答灯の色は「表示器の色」で選ぶ。

## 開発フェーズと未決事項

まず`core`の運転曲線と、2階床・1台のかごの昇降から着手する。

**フェーズ（案）**

1. 2階床・1台：かごの移動、プレイヤーの運搬、当たり判定、扉、ボタン
   - ウィザード設置とボタンができるまでは、デバッグ用コマンドで設置・運転する（`/realelevator spawn <かごを置く階の床面> <機種> <向き> <速度> <ほかの停止階のY…>`（停止階の間隔は4ブロック以上）、`call <階>`（かご呼び）、`hall <階> [up|down]`（乗場呼び）、`open`、`close`、`remove`、`config <panel|car_indicator|left_indicator|hall_indicator|hall_lantern|arrival_announcement|close_announcement|chime> <値>`（配置とアナウンスの設定））。
   - デザインシステムができるまでは、バニラのテクスチャを流用する（壁：鉄ブロック、床：磨かれた安山岩、天井：滑らかな石）。
2. 階床表示、チャイム、同梱音声によるアナウンス、多階床対応、ウィザード設置、高速仕様（ネザースター）、昇降路の機構の描画
3. 車椅子用操作盤、2度押しキャンセル、多光軸ビーム、強制戸閉、運転と休止（休止に切り替えたときの自動着床）、ランディングオープン
4. デザインシステム（素材、プリセット、防犯窓、トランサム、展望）。次の順に小分けして進める。
   1. 部品の見た目：ボタン（四角、面の図柄）、主操作盤の縦長の板、車椅子用操作盤の板、表示器の大きい字と色の選択
   2. かご内装：素材の仕組み（タグ、部位ごとの素材）、オリジナルのドット絵、壁の継ぎ目、幅木、天井3種、かご内の明るさ、手すり
   3. 乗場：細枠・幕板付き、壁付けと埋め込みの操作盤、カメレオンの壁、敷居、ホールランタンの位置と背面プレート、群管理向けの設定
   4. 防犯窓と展望仕様：網入りガラス、腰壁付きのガラスの奥壁
   5. プリセットと設定画面：プリセットのデータパック対応、部位ごとの素材の選択画面
   6. かごの外側とガイド：T形レール、ローラーガイド、かご枠、ドアオペレーター、エプロンと非常止め、かご上の安全柵、かごの外側の面の明るさをまわりに合わせる（かご内の照明の明るさが外に効かないように）、乗場の三方枠の範囲を昇降路の側（裏）からも描く
5. VOICEVOX連携、複数台の群管理。次の順に小分けして進める。
   1. VOICEVOX連携：クライアントの設定と設定画面、合成と再生、キャッシュ、同梱音声へのフォールバック、停止階の読み上げ名
   2. 複数台の群管理
   3. プロファイルと仕様書：仕様と意匠の保存と読み込み（手元のファイルと仕様書のアイテム）
   4. レシピと設置の材料
6. ベータ版（1.0.0-beta）をふだんの環境で試して出た課題。各項目の仕様は、それぞれの節に書いてある。
